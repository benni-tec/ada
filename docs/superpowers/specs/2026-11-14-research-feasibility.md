## Exa

### Search
`POST https://api.exa.ai/search`. Sent (`exa-search-data-request.json`):
`{"query": "cancer survival by hospital district Finland", "type": "auto", "numResults": 5,
"includeDomains": [sotkanet.fi, thl.fi, stat.fi, pxdata.stat.fi, syoparekisteri.fi,
cancerregistry.fi, iarc.who.int, gco.iarc.fr, ec.europa.eu, oecd.org, who.int, kela.fi,
duodecim.fi, avoindata.fi, zenodo.org, kaggle.com, figshare.com],
"contents": {"highlights": {"maxCharacters": 600}}}`.
Response fields needed: `results[].url`, `.title`, `.publishedDate` (often null or absent),
`.highlights[]` (snippet, list of strings), `.id` (equals the url); also `requestId` and
`costDollars.total` (0.007 for 5 results). Hits: cancerregistry.fi and syoparekisteri.fi pages
and Sotkanet indicator 3625. Highlights start with page navigation text, so a snippet is rough.

### Contents
`POST https://api.exa.ai/contents`. Sent: `{"urls": [<sotkanet 3625 metadata url>],
"text": {"maxCharacters": 3000}}`. Fields: `results[].url/.title/.text/.author`,
`statuses[].status` (`success` or `error`) and `.source` (`cached` or `crawled`),
`statuses[].error.tag/.httpStatusCode` on errors, `costDollars.total` (0.001). Per-URL errors
come back inside HTTP 200, so code must read `statuses`. `maxAgeHours: 0` forces a live fetch.

## Context.dev (base `https://api.context.dev/v1`)

Differences from the plan: scrape and extract are the **same** endpoint, `POST /web/scrape`,
chosen by `formats`. The monitor webhook secret comes back in the create answer.
`sharedParams.maxAgeMs` is documented but **rejected** (400 `INPUT_VALIDATION_ERROR`, unknown
key): do not send it. Failed validation costs no credits.

### Read a page (Markdown)
`POST /web/scrape`. Sent (`context-scrape-request.json`): `{"url":
"https://sotkanet.fi/sotkanet/en/metadata/indicators/3625", "formats": {"markdown": true},
"sharedParams": {"mainContentOnly": true}, "markdownParams": {"includeLinks": false}}`.
Response: `markdown.success` (bool), `markdown.data` (the text), `metadata.title`,
`metadata.language`, `cache_metadata`, `key_metadata.credits_remaining`. Unrequested formats
come back as `{requested: false, success: null, data: null}`. Read failures keep HTTP 200 with
`success: false` plus `error_code` and `message` (also for PDFs, e.g. `PDF_IMAGES_ONLY`);
only request validation errors are HTTP 400 with top-level `error_code` and `message`.
PDFs use the same call with the PDF url (tested: the 2023 annual report, 105,841 characters).
The Sotkanet page came back as clean Markdown tables.

### Extract with a schema
`POST /web/scrape`. Sent (`context-extract-request.json`): `{"url": <same page>,
"formats": {"json": true}, "jsonParams": {"schema": {"type": "object", "properties":
{"rows": {"type": "array", "items": {...field, value...}}}, "required": ["rows"]},
"instructions": "..."}}`. The schema must be a top-level object (wrap lists in a property,
here `rows`), at most 50 KB; `instructions` at most 2,000 characters. Response: `json.success`,
`json.data` (the object, here `{"rows": [{"field", "value"}, ...]}`), `json.isTruncated` when
the page exceeds 100,000 characters (the PDF read was cut there). Use nullable fields for
values a page may lack, or the model guesses.

### Monitors
Create: `POST /monitors`, sent (`context-monitor-create-request.json`): `{"name": ...,
"target": {"type": "page", "url": "https://example.com/"}, "webhook": {"url": ...,
"events": ["change.detected"]}, "schedule": {"type": "interval", "frequency": 1,
"unit": "days"}}`. Answer 201: `id` (`mon_...`), `status` (`active`), `webhook.secret`
(generated by Context.dev, stored by us), `change_detection.type` (`exact` by default),
`next_run_at`, `initial_run_id` (a baseline run starts at once). Interval: 10 minutes to
1 year. Created and deleted in one script (monitor deleted, `deleted: true`).
Delete: `DELETE /monitors/{id}` answers 200 `{"id", "deleted": true}`
(`context-monitor-delete.json`). Both cost 0 credits on this account.
Webhook (from the docs, not received here): headers `X-Context-Signature: t=<unix>,v1=<hex>`,
`X-Context-Event`, `X-Context-Id` (stable across retries, use to deduplicate). Signature =
HMAC-SHA256 hex over `"{t}.{raw body bytes}"` with the full secret string; reject timestamps
more than 5 minutes off. Body: `{event, id, created_at, data}` with `data.change` and `data.run`.
The docs do not list their fields; treat everything below `data` as opaque and on a hit
re-read the page with `/web/scrape`. A real delivery is needed to learn the fields.

## Cancer Registry check (county-level survival)

Result: **no usable county table.** Per the spec, that item drops.
- `https://cancerregistry.fi/statistics/` and `.../most-important-statistics/`: scrape works
  (the site does not block Context.dev) but they only link to the interactive application.
- `https://tilastot.syoparekisteri.fi/syovat/?...in.subset.area=["101L",...,"600L"]...` (the 22
  areas; an R Shiny app): scrape returned 287 characters of empty page chrome, no table. The
  CSV/XLSX export is a browser download, out of reach of the scrape call.
- `https://syoparekisteri.fi/2020/06/23/asuinpaikka-vaikuttaa-...` (news item): prose only.
- `https://syoparekisteri.fi/assets/files/2025/06/Syopa_2023_en.pdf` (Cancer in Finland 2023):
  scrape reads the PDF as text. Chapter 12 gives the 2019-2023 five-year survival per cancer
  nationwide (breast 93.0 %, colorectal 69.8 %, lung 25.6 % women, 16.2 % men) and names in
  sentences the wellbeing services counties significantly above or below it. The per-county
  values sit only in figures (images): the Markdown has 0 table rows, and a schema extract for
  per-county survival returned `rows: []`.
- Usable instead: the county names that differ significantly (prose, citable), and Sotkanet
  3625-3627 for hospital districts. Registry numbers per county would need the browser export.
